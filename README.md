# Toltec — редактор объектов

JavaFX-приложение для создания и редактирования объектов игры (полов, юнитов и
декоративных/интерактивных объектов) поверх существующего игрового движка
(`org.toltec.*`). Редактор — это отдельный слой `org.toltec.editor.*` сверху
плюс несколько небольших, обратно-совместимых доработок самого движка (см.
«Изменения в движке» ниже).

Сам движок разложен по пакетам-ролям вместо одной плоской папки:

| Пакет               | Что там                                                        |
|---------------------|-----------------------------------------------------------------|
| `org.toltec.engine` | `TileGameEngine`, `EngineOptions`, `GameCanvas`, `MapCell`, `PathFinder`, `GpuAcceleration` — цикл игры, карта, камера |
| `org.toltec.render` | `GraphicObject`, `AnimationClip`, `AssetStorage`, `ObjectTextureConfig`, `TileTextureConfig`, `TileType` — спрайты, анимации, конфиги текстур |
| `org.toltec.unit`   | `Unit`, `Player`, `Goblin`, `Damageable`, `UnitAnimationConfig`, `UnitStatus`, `Gender`, `Direction8` — юниты и бой |
| `org.toltec.demo`   | `Main`, `ExampleGame`, `UnitDemoGame` — примеры запуска движка отдельно от редактора |
| `org.toltec.editor` | сам редактор (без изменений, как раньше)                        |
| `org.toltec.tools`  | `TileCutter` и подобные разовые утилиты (без изменений)          |

Публичный API классов не менялся — только `package`-строка и, соответственно,
`import`. Если у вас есть свой код поверх этого движка вне данного репозитория,
после обновления замените `import org.toltec.ИмяКласса;` на
`import org.toltec.<пакет>.ИмяКласса;` по таблице выше (в IDE это обычно
делает автодополнение/organize-imports само).

## Запуск

```bash
mvn javafx:run
```

Это откроет редактор (`org.toltec.editor.EditorApp`). Для запуска ваших
демо-игр по-прежнему используйте обычный способ, например:

```bash
mvn compile exec:java -Dexec.mainClass=org.toltec.demo.UnitDemoGame
```
(или запустите нужный класс `main` прямо из IDE — как раньше).

> Собранный `.jar` (`mvn package`) запускает редактор по умолчанию, но
> `java -jar …jar` без JavaFX в classpath работать не будет — у JavaFX
> артефактов `org.openjfx` нет «толстого» бандла в этом pom. Для повседневной
> работы используйте `mvn javafx:run` или запуск из IDE.

## Как устроен редактор

- **Слева** — каталог объектов, три вкладки (Полы / Юниты / Объекты) плюс
  кнопки «Новый», «Клонировать», «Удалить» — действуют на активную вкладку и
  выделенный объект.
- **Сверху** — название объекта, бейдж категории и (для юнитов —
  пол/оружие/состояние, для объектов — состояние + флаг «всенаправленный»)
  выбор того, какая именно комбинация сейчас редактируется в сетке.
- **По центру** — сетка 3×3. Центральная клетка — это по-настоящему
  запущенный `TileGameEngine` (поле 5×5, редактируемый объект — в центре).
  Остальные 8 клеток — это 8 изометрических направлений; для полов активны
  только 4 (С/В/Ю/З — как в `TileTextureConfig`), для «всенаправленных»
  объектов — только одна. Кликните клетку, чтобы выбрать направление (превью
  сразу повернётся), перетащите картинку(и) из палитры справа или прямо из
  проводника — можно бросить сразу несколько файлов, это уже готовая
  анимация. Двойной клик / контекстное меню открывает список кадров
  (добавить/удалить/переставить местами).
- **Справа** — палитра: «Импортировать файлы…», «Открыть папку…», плюс при
  открытии существующего объекта туда же подтягиваются его собственные
  картинки — удобно пересобрать анимацию заново.
- **Снизу** — все параметры, которые понимают конфиги движка: для текущей
  комбинации — длительность (мс)/скорость/зацикленность/порядок/масштаб, и
  отдельно — то, что относится ко всему объекту целиком (проходимость,
  урон/сек, боевые шансы юнита, коллизия/слой/размер объекта и т.д.)

По кнопке **«Сохранить»** создаётся папка
`src/main/resources/{floors|units|objects}/<Название>/`, туда копируются
использованные картинки (с именами вида `<Название>_<состояние>_<угол>.png`,
без пробелов и спецсимволов) и пишется `<Название>.ini` — в точности в том
формате, который понимают `TileTextureConfig` / `UnitAnimationConfig` /
`ObjectTextureConfig`.

Живое превью в центре — это не рендер «понарошку»: оно каждый раз
пересобирает временный `.ini` и грузит его тем же самым загрузчиком, что и
настоящая игра (просто по абсолютным путям к оригинальным файлам, без копий,
пока вы не нажали «Сохранить») — то есть что видите, то и получите.

## Заметки по интерфейсу

- **Только масштабирование в превью.** Колесо мыши / клавиши +/- масштабируют
  камеру в центральной клетке; панорамирования (перетаскивание правой кнопкой,
  автопрокрутка у края) там намеренно нет — превью всегда показывает объект
  целиком по центру, без какой-либо прокрутки. Поле 5×5 отрисовывается строго
  по центру клетки — кнопки поворота теперь плавают поверх картинки снизу, а
  не занимают часть той же клетки (раньше из-за этого поле оказывалось выше и
  левее центра).
- **Настоящая нарезка анимации по кадрам.** Если в клетку падает одна картинка
  с несколькими кадрами на прозрачном фоне (кадры разделены полностью
  прозрачными строками/столбцами), при сохранении и в превью она автоматически
  считается анимацией — движок сам режет её по кадрам при загрузке, вручную
  резать картинку заранее не нужно. Обычная одиночная картинка без внутренних
  прозрачных промежутков по-прежнему остаётся статичной позой.
- **Направления.** У каждой клетки — русское и английское обозначение (С · N,
  ЮВ · SE и т.д.), полы используют только 4 стороны (С/В/Ю/З), всенаправленные
  объекты — только одну клетку.
- **Все панели раздвижные.** Между каталогом/центром/палитрой и между сеткой и
  параметрами — обычные ползунки `SplitPane`, тяните в любую сторону.
- **Маркеры заполненности.** В выпадающих списках «Состояние» (и «Оружие» для
  юнитов) жёлтая точка — есть кадры, но не все направления, зелёная галочка —
  заполнено ≥4 направлений.
- **Перетаскивание добавляет, а не заменяет.** Кидаете картинку за картинкой
  на одну клетку — они выстраиваются в кадры анимации по порядку; один
  оставшийся кадр = статичная поза. Полностью очистить клетку — через
  контекстное меню или диалог кадров (двойной клик).
- **Палитра справа**: помнит последнюю открытую папку, есть рекурсивный поиск
  по подпапкам, регулировка размера превью и фон под прозрачность (тёмный /
  светлый / шахматка — тот же фон используется и в клетках направлений),
  поиск по названию и фильтр по ключевым словам (выделяются из названий файлов
  автоматически, без углов — `Attack_Bow_000` → `attack`, `bow`).
- **Автоимпорт.** «Автоимпорт углов» раскладывает видимые (после фильтра)
  картинки по клеткам текущей комбинации, ища в названии направление (числа
  вроде `045`/`180` или `N/NE/…`, `С/СВ/…`). «Импорт состояний» (только для
  юнитов) вдобавок распознаёт состояние (`Attack`, `Idle`…) и оружие (`sword`,
  `bow`…) и сразу заполняет все подходящие комбинации.

## Формат `objects/<Имя>/<Имя>.ini`

Для юнитов и полов формат — это ваш собственный, без изменений. Для
объектов (новая категория) — по образцу тех же двух, но проще:

```ini
basedir=./

anim[closed][*]   = closed_0.png|closed_1.png   # уже готовые кадры
img[open][0]      = open_S.png                   # статичная поза, конкретное направление

duration[open][*] = 300
loop[closed][*]    = true
scale[*][*]        = 1.0                          # (пример — пишется только если задано)

collision  = true
layer      = 3
isometric  = true
drawWidth  = -1
drawHeight = -1
fitToCell  = true
fitScale   = 1.0
xOffset    = 0
yOffset    = 0
sizeCols   = 1
sizeRows   = 1
```

Чтобы подключить это к своей игре, аналогично `TileTextureConfig`/
`UnitAnimationConfig`:

```java
ObjectTextureConfig doorCfg = new ObjectTextureConfig(assets);
doorCfg.load("/objects/Door/Door.ini");           // classpath — как обычно
// doorCfg.load(Path.of("objects/Door/Door.ini")); // или напрямую с диска

AnimationClip clip = doorCfg.resolve("closed", Direction8.S);
GraphicObject door = new GraphicObject(clip.frame(0));
doorCfg.applyTo(door);   // collision/layer/isometric/размер/оффсеты одним вызовом
cell.addObject(door);
```

(Если объекту нужна анимация со сменой кадров по времени — на превью в
редакторе используется маленький хелпер `AnimatedPreviewObject`
(`org.toltec.editor.preview`), который просто шагает по `AnimationClip`; при
желании вынесите его в основной пакет движка — он ни от чего в `editor.*` не
зависит.)

## Изменения в движке (обратно совместимые)

Всё, что перечислено ниже, не меняет поведение существующих `ExampleGame`/
`UnitDemoGame`/`Player`/`Goblin` — это либо чисто аддитивные перегрузки, либо
внутренняя деталь реализации `GameCanvas`.

1. **`GameCanvas` теперь `JPanel`, а не `Canvas`.**
   Публичный API не изменился (конструктор, `paint`/события — всё то же
   самое поведение через Swing), но теперь его можно встраивать не только в
   `JFrame`, но и в JavaFX `SwingNode` — `SwingNode` в принципе не
   поддерживает тяжеловесные AWT-компоненты вроде `Canvas`, только
   легковесные Swing. Именно так работает центральная клетка превью.

2. **`TileTextureConfig.load(Path)` и `UnitAnimationConfig.load(Path)`** —
   те же самые форматы и то же разрешение путей (`basedir=`), что и у
   версий с classpath-ресурсом, но читают файл прямо с диска — путь может
   быть как относительным (к самому `.ini`), так и абсолютным (тогда
   ссылается на исходный файл где угодно на диске, без необходимости его
   куда-то класть заранее). Нужно для живого превью и вообще для любых
   инструментов/модов, работающих не через classpath.

3. **`AssetStorage.loadImageTrimAlpha(String, Path)`** — файловый аналог
   `loadImageResourceTrimAlpha`, тем же способом.

4. **`ObjectTextureConfig`** — новый класс, отдельная третья категория
   контента (см. выше), которой раньше не было вообще.

5. **`AssetStorage.loadAnimationTrimAlpha` / `loadAnimationResourceTrimAlpha`**
   — нарезка анимационного листа по полностью прозрачным строкам/столбцам,
   без явного `bgcolor=`. `UnitAnimationConfig`/`ObjectTextureConfig` теперь
   используют это автоматически, когда лист грузится без `bgcolor=` в
   конфиге (`bgcolor=` по-прежнему работает как раньше — нарезка по сплошному
   цвету, если он задан, в приоритете).

6. **Картинки для юнитов/объектов больше не обрезаются, а листы анимации
   режутся ровной сеткой.** `UnitAnimationConfig`/`ObjectTextureConfig`
   теперь грузят и статичные позы, и уже готовые кадры через
   `AssetStorage.loadImageNoTrim`/`loadImageResourceNoTrim` — полный холст
   картинки, без обрезки по альфе/цвету фона. Однофайловый лист
   (`anim[...] = sheet.png`) режется через
   `AssetStorage.loadAnimationGrid(TrimAlpha)`/`loadAnimationGridResource(TrimAlpha)`:
   количество строк/столбцов определяется тем же способом, что и раньше
   (полностью прозрачные/фоновые строки-столбцы-разделители), но сама
   нарезка — на N×K РОВНЫХ прямоугольников (без обрезки по содержимому
   каждой ячейки), поэтому все кадры одного размера и с одинаковой точкой
   привязки.
   <br>
   На это завязаны новые `sizeCols`/`sizeRows` у `ObjectTextureConfig`
   (по умолчанию `1`×`1`) → `GraphicObject#footprintCols`/`#footprintRows`:
   объект с footprint C×R (colов вправо, rowов вниз от исходной клетки)
   при отрисовке автоматически опускается на
   `((C+R)/2) * cellHeight/2` — для «1×1» это `cellHeight/2`, для «2×2» —
   `cellHeight` (т.е. `2 * cellHeight/2`), вместо одного и того же
   фиксированного отступа независимо от размера. Если `fitToCell=true`,
   рисуемая ширина ТАКЖЕ умножается на этот же коэффициент `(C+R)/2`, чтобы
   объект визуально накрывал весь свой footprint, а не сжимался под ширину
   одной клетки. `GraphicObject#footprintCols`/`#footprintRows` по
   умолчанию `0` (т.е. «не задано, ничего не менять»), поэтому это не
   трогает существующих юнитов и объекты, созданные вручную в коде — только
   объекты, у которых `ObjectTextureConfig` явно проставил эти поля.
   <br>
   **Важно:** это влияет ТОЛЬКО на визуальный отступ/размер — объект по
   прежнему живёт ровно в одной `MapCell` (той, куда его положили).
   Реального занятия/коллизии по соседним клеткам footprint нет — это
   отдельная, более крупная доработка (`MapCell` сейчас — список объектов на
   ОДНУ клетку, без понятия «объект размером в несколько клеток»).

7. **`TileGameEngine#debugAnchors`** — отладочная разметка (выключена по
   умолчанию, `public volatile boolean`, ни на что не влияет кроме
   отрисовки): жёлтая рамка вокруг фактического прямоугольника картинки,
   красная точка на её нижней грани и голубая точка в опорной точке клетки
   (центр изометрического ромба / центр клетки в top-down). В редакторе
   включается кнопкой «⊹» рядом со стрелками поворота в превью
   (`PreviewPane`, теперь под холстом, а не поверх него) — удобно, чтобы
   визуально проверить, куда именно встаёт `yOffset`/`footprintCols`/`footprintRows`.

8. **`fitToCell`/`sizeCells` теперь есть и у юнитов**, не только у объектов
   — `UnitAnimationConfig`: `fitToCell[gender][weapon][*][*] = true` (масштабировать
   под ширину клетки вместо натурального размера пикселей — тем самым решает
   «картинка огромная» в редакторе) и `sizeCells[gender][weapon][*][*] = N`
   (квадратный footprint N×N, тот же принцип отступа, что у объектов —
   только один параметр, не `sizeCols`/`sizeRows` отдельно, юниты
   несимметричный footprint не поддерживают). В отличие от
   `ObjectTextureConfig`, здесь НЕТ инженерного дефолта: если строку не
   писать вообще, юнит рендерится ровно как раньше (никакого отступа) — это
   специально, чтобы `Player`/`Goblin`/`UnitDemoGame` со старыми `units.ini`
   не сдвинулись. Редактор при создании юнита пишет `sizeCells=1`/
   `fitToCell=true` явно (см. `ParamsPanel`'s «РАЗМЕР НА КЛЕТКЕ»), поэтому
   юниты, созданные через него, получают отступ/подгонку по умолчанию так
   же, как объекты.

## Структура проекта

```
src/main/java/org/toltec/            движок — без изменений в логике (см. выше)
src/main/java/org/toltec/editor/     редактор
    model/                           EditableObject и всё, что он держит
    io/                              чтение/запись .ini, работа с файловой системой
    preview/                         PreviewEngine/PreviewService — живое превью
    ui/                              JavaFX-компоненты
    EditorApp.java                   точка входа
src/main/resources/
    floors/ units/ objects/          сюда редактор сохраняет объекты
    tiles.ini, units.ini, …          ваши существующие общие конфиги — не тронуты
```
